# CardLyze — High-Risk Transaction Monitoring & Report Platform

CardLyze is a secure, privacy-first financial intelligence web platform and automated reporting engine for debit and credit card transactions across major card providers (**VISA**, **PineLabs**, and **Vegapay**).

It serves two primary operational functions:
1. **TMS-ATM Automated Monitoring & Cumulative Alert Engine**: Automated daily ATM cash-out pattern detection, cumulative high-risk watchlist compilation, and report archiving.
2. **Column Addition & In-Memory Data Pipeline**: Zero-disk-persistence workbook header mapping, data quality normalization, in-memory preview, and fast streaming export.

## 🚀 Quick Start with Docker (Recommended)

Docker provides an isolated, out-of-the-box environment without needing to install Python or configure local environment variables.

### 1. Prerequisites
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows / macOS / Linux)

### 2. Launch the Application
From the repository root:

```bash
docker compose up --build
```

### 3. Open the Application
Navigate to the TMS Dashboard in your browser:
- **TMS Dashboard**: [http://localhost:8000/task1.html](http://localhost:8000/task1.html)
- **Reports & Archive**: [http://localhost:8000/reports.html](http://localhost:8000/reports.html)
- **Column Addition Tool**: [http://localhost:8000/column-addition.html](http://localhost:8000/column-addition.html)

> **Volume Sync**: Any `.xlsx` reports generated by the container are automatically mirrored to your local `./report_generation/day_output_files/` and `./report_generation/cumulative_output_files/` directories.

To stop the container:
```bash
docker compose down
```

## 🛡️ TMS-ATM Business Logic & Rule Engine

### 1. Daily ATM Cash-Out Detection Rule
An individual cardholder is flagged if, within a single calendar day:
- **ATM Transaction Frequency** > 3
- **Total ATM Volume** > $1,500.00 USD (equivalent converted via card-specific exchange rates)
- **ATM Merchant Category Codes (MCC)**: `6011` (Automated Cash Disburse), `6010` (Financial Inst - Manual Cash), `6050`, `6051` (Quasi-Cash).

### 2. Cumulative Watchlist (Threshold: > 3 Days)
- Every day an individual breaches the ATM cash-out rule, an alert is added to their record in `report_generation/alert_ledger.json` (`+1 Alert`).
- When an individual accumulates > 3 distinct alert days (configurable via `CARDLYZE_CUMULATIVE_ALERT_THRESHOLD`), they breach the watchlist threshold.
- The system automatically compiles a **Full History Dossier** (`cumulative_<card>_<acct>.xlsx`) containing the individual's entire lifetime transaction history across all MCCs and dates.

### 3. Automated Daily Execution & Catch-Up
- The background scheduler executes daily at 12:15 AM IST (configurable delay after midnight).
- Automatically queries the completed previous calendar day, executes rules, updates the ledger, and writes formatted Excel reports to `/day_output_files`.
- **Startup Catch-Up**: If the server was offline past midnight, it checks for missing yesterday reports on boot and backfills them automatically.

## 🗄️ Database Integration (AWS RDS MS SQL Server)

The application is pre-configured with a repository abstraction layer ([`app/services/data_provider.py`](file:///app/services/data_provider.py)):

1. **Simulation Mode (`file`)**: Reads daily and monthly Excel workbooks from `report_generation/input_files` and `data_with_headers/`.
2. **Database Mode (`sql`)**: Connects to AWS RDS MS SQL Server via SQLAlchemy and ODBC Driver.

To switch to direct database queries:
1. Connect to your organization VPN (e.g. OpenVPN).
2. Install optional database drivers:
   ```bash
   pip install -r requirements-db.txt
   ```
3. Set environment variables in `.env` or `docker-compose.yml`:
   ```env
   CARDLYZE_DATA_PROVIDER=sql
   CARDLYZE_DB_HOST=your-rds-endpoint.amazonaws.com
   CARDLYZE_DB_PORT=1433
   CARDLYZE_DB_NAME=tms_atm_db
   CARDLYZE_DB_USER=your_db_user
   CARDLYZE_DB_PASSWORD=your_db_password
   CARDLYZE_DB_DRIVER=ODBC Driver 17 for SQL Server
   ```

*The verified production T-SQL queries and schema documentation are located in [`task_1/tms_atm_task1_queries.sql`](file:///task_1/tms_atm_task1_queries.sql) and [`task_1/SQL_QUERIES_EXPLAINED.md`](file:///task_1/SQL_QUERIES_EXPLAINED.md).*

## ☁️ Cloud Storage & Local S3 Emulation (LocalStack)

CardLyze includes an **S3 Cloud Storage Adapter** ([`app/services/s3_storage.py`](file:///app/services/s3_storage.py)) for automated cloud report archiving and alert ledger synchronization:

1. **Local Mode (Default)**: Saves generated `.xlsx` spreadsheets and `alert_ledger.json` strictly to local folders.
2. **AWS S3 Mode**: Uploads daily reports (`s3://bucket/daily_reports/...`), cumulative dossiers (`s3://bucket/cumulative_reports/...`), and synchronizes the alert ledger (`s3://bucket/metadata/alert_ledger.json`).
3. **LocalStack Mode ($0 Free Local Emulator)**: Emulates AWS S3 locally via Docker with 100% offline simulation and zero AWS charges.

### Testing S3 Locally via LocalStack
Start CardLyze alongside LocalStack with one command:

```bash
docker compose --profile cloud-mock up
```

LocalStack exposes S3 at `http://localhost:4566`. In `.env` or `docker-compose.yml`, configure:

```env
CARDLYZE_STORAGE_BACKEND=s3
CARDLYZE_S3_ENDPOINT_URL=http://localhost:4566
CARDLYZE_S3_BUCKET=cardlyze-reports
AWS_ACCESS_KEY_ID=test
AWS_SECRET_ACCESS_KEY=test
```

The system automatically auto-creates the bucket if missing and streams batch reports to local S3.

## ⚙️ Configuration Reference

All settings can be customized via environment variables:

| Variable | Default | Description |
|---|---|---|
| `CARDLYZE_HOST` | `127.0.0.1` (`0.0.0.0` in Docker) | Host address to bind the server. |
| `CARDLYZE_PORT` | `8000` | Port to bind the server. |
| `ALLOW_NON_LOOPBACK` | `0` (`1` in Docker) | Allows external interface binding. |
| `CARDLYZE_REPORT_TIMEZONE` | `Asia/Kolkata` | Timezone for daily midnight calculations. |
| `CARDLYZE_DAILY_RUN_DELAY_MINUTES` | `15` | Delay in minutes after midnight for automated run (e.g. `15` = 12:15 AM). |
| `CARDLYZE_AUTO_SCHEDULER_ENABLED` | `1` | Enable/disable background recurring scheduler. |
| `CARDLYZE_STARTUP_CATCHUP_ENABLED` | `1` | Enable/disable backfill check on server boot. |
| `CARDLYZE_FREQUENCY_THRESHOLD` | `3` | ATM transactions per day required to trigger alert. |
| `CARDLYZE_USD_THRESHOLD` | `1500.0` | Total USD equivalent volume per day required to trigger alert. |
| `CARDLYZE_CUMULATIVE_ALERT_THRESHOLD` | `3` | Number of alert days required to trigger full history dossier. |
| `CARDLYZE_DATA_PROVIDER` | `file` | Data provider: `file` (simulation) or `sql` (AWS RDS). |
| `CARDLYZE_STORAGE_BACKEND` | `local` | Report storage destination: `local` (disk) or `s3` (AWS S3 / LocalStack). |
| `CARDLYZE_S3_BUCKET` | `cardlyze-reports` | Target AWS S3 bucket name. |
| `CARDLYZE_S3_ENDPOINT_URL` | *None* | Custom S3 endpoint URL (set to `http://localhost:4566` for LocalStack). |
| `CARDLYZE_S3_SAVE_CLEAN_REPORTS` | `1` | Set to `0` to skip uploading clean reports (0 alerts) to S3, reducing API calls. |

## 🔒 Security & Privacy Model

- **Strict Content Security Policy (CSP)**: `default-src 'self'`. Zero inline event handlers (`onclick`), zero inline CSS `style="..."`, zero `eval()`.
- **Zero Disk Persistence (Column Addition)**: Header mapping and data previews reside strictly in RAM (`io.BytesIO`) and ephemeral in-memory session structures.
- **Controlled File Output**: Reports generated by the TMS engine are written strictly to designated, audit-trailed output directories with metadata checksums.
